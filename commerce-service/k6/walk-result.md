## 시나리오 1. 주변 산책 코스 목록 조회

### 테스트 대상

| 항목 | 값 |
| --- | --- |
| 대상 API | `GET /walk/course/nearby?lat={lat}&lng={lng}&page={page}&size=3` |
| 기능 | 산책 화면에서 지도 위치 기준으로 주변 코스를 목록에 표시 |

### 시나리오

실제 화면과 같이 서울 시청 부근 약 500m 범위의 좌표와 페이지(0 또는 1)를 섞어 요청했습니다. 각 가상 사용자는 목록 요청 뒤 다음 지도 조작 전까지 1~3초간 대기합니다.

| 단계 | 시간 | 목표 VU |
| --- | ---: | ---: |
| 램프업 1 | 3초 | 50 |
| 램프업 2 | 5초 | 200 |
| 램프업 3 | 5초 | 500 |
| 피크 유지 | 5초 | 500 |
| 램프다운 | 5초 | 0 |

> 이 결과는 `QUICK=true` 압축 스파이크 프로파일입니다. 장시간 안정성 검증에는 `walk-nearby.js`의 기본 5분 30초 프로파일을 사용합니다.

### 결과

| 지표 | 결과 | 판정 |
| --- | ---: | --- |
| 최대 동시 사용자 | 500 VU | - |
| 총 HTTP 요청 | 3,350 | - |
| 평균 처리량 | 130.38 req/s | - |
| HTTP 실패율 | 0.00% | 통과 |
| 평균 응답 시간 | 13.18ms | - |
| P90 응답 시간 | 18.92ms | - |
| P95 응답 시간 | 21.29ms | 통과 |
| P99 응답 시간 | 31.50ms | 통과 |
| 최대 응답 시간 | 61.99ms | - |
| 응답 검증 | HTTP 200 및 JSON 3,350건 모두 성공 | 통과 |

### 결론

500 VU 피크 상황에서도 오류 없이 응답 시간 기준을 충족했습니다. 다만 이 엔드포인트는 MySQL의 `ST_Distance_Sphere` 거리 계산과 정렬을 사용하므로, 코스 데이터가 크게 증가한 뒤에는 기본 장시간 시나리오와 MySQL slow query log/실행 계획을 함께 확인합니다.

## 시나리오 2. 임시 코스 1,000개 기반 주변 목록 조회

### 테스트 대상

`GET https://decfour.dev/walk/course/nearby?lat={lat}&lng={lng}&page={page}&size=3`

### 테스트 환경

| 항목 | 값 |
| --- | --- |
| 실행 일시 | 2026-08-19 (KST) |
| 대상 서버 | `https://decfour.dev` |
| 임시 데이터 | 중심점 1km 이내 산책 코스 1,000개 |
| 가상 사용자 | 최대 500 VU |
| 프로파일 | 50 → 200 → 500 VU 램프업, 500 VU 5초 유지, 램프다운 |
| 테스트 시간 | 23초 압축 스파이크 |
| 데이터 정리 | `test` 계정으로 생성 후 실행 ID로 재조회·전량 삭제 검증 |

### 결과

| 지표 | 결과 | 판정 |
| --- | ---: | --- |
| 임시 코스 생성 | 1,000 / 1,000 | 성공 |
| 임시 코스 잔존 | 0 | 삭제 검증 통과 |
| 목록 조회 반복 | 2,182회 | - |
| 전체 HTTP 요청 | 4,185건 | - |
| HTTP 실패율 | 0.00% | 통과 |
| 목록 조회 평균 응답 시간 | 1.22s | - |
| 목록 조회 P90 | 3.40s | - |
| 목록 조회 P95 | 3.53s | 실패 |
| 목록 조회 P99 | 6.28s | 실패 |
| 목록 조회 최대 응답 시간 | 9.21s | - |

### 결론

기존 데이터 조건의 시나리오 1과 달리, 주변 1km 내 코스가 1,000개인 상황에서는 P95 1초·P99 2초 기준을 초과했습니다. 조회 실패는 없었지만, `ST_Distance_Sphere`를 계산하고 정렬하는 현재 쿼리는 데이터 증가와 동시 요청에 선형적으로 취약합니다. 다음 개선 검증에서는 위치를 `POINT` 컬럼으로 모델링하고 SPATIAL INDEX를 적용하거나, 위도·경도 범위(Bounding Box)로 먼저 후보를 줄인 뒤 거리 계산·정렬하는 방식을 비교합니다.
