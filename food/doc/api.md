# FoodLab API 명세서

기본 경로는 `/api/v1`이다. 요청·응답은 JSON을 사용하며, 이미지 업로드 요청은 `multipart/form-data`를 사용한다. 경로와 필드명은 검토용이다.

## 인증 및 회원

| 메서드 | 경로 | 접근 | 설명 |
| --- | --- | --- | --- |
| POST | `/auth/signUp` | 공개 | `email`, `password`, `name`으로 가입 |
| POST | `/auth/signIn` | 공개 | 이메일과 비밀번호로 로그인 |
| POST | `/auth/refresh` | 리프레시 쿠키 | 새 액세스 토큰 발급 및 리프레시 토큰 교체 |
| POST | `/auth/signOut` | 리프레시 쿠키 | 리프레시 토큰 폐기 및 쿠키 제거 |
| GET / PATCH | `/members/me` | 회원 | 내 회원 정보 조회 / 표시 이름(`name`) 수정 |
| GET | `/members/me/dishes` | 회원 | 내가 등록한 요리 목록 |
| GET | `/members/me/reviews` | 회원 | 내가 작성한 평가 목록 |

내 요리·평가 목록은 JWT의 회원 ID로 조회하며 최신 등록순으로 반환한다. `page`는 기본 0이고 `size`는 기본 20, 최대 100이다. 각 항목은 공개 요리·평가 목록과 같은 형식이다.

- 비밀번호는 BCrypt로 해시해 저장한다.
- 로그인과 갱신은 수명이 15분인 JWT 액세스 토큰을 응답 본문으로 반환한다. React는 토큰을 메모리에 보관하고 회원 전용 API 요청에 `Authorization: Bearer <accessToken>` 헤더를 보낸다.
- 리프레시 토큰의 수명은 발급 시점부터 7일이다. 브라우저에는 `HttpOnly` 쿠키로 전달하고 서버에는 해시만 저장한다. 갱신에 성공하면 기존 리프레시 토큰을 폐기하고 새 토큰과 쿠키를 발급한다.
- 로그아웃은 쿠키에 해당하는 리프레시 토큰을 폐기하고 쿠키를 제거한다. 이미 발급된 액세스 토큰은 만료까지 유효하다.
- 가입 성공은 `201`과 `{ "memberId": 1 }`을 반환한다. 로그인·갱신 성공은 `200`과 `{ "accessToken": "..." }`을 반환한다. 로그아웃은 `204`를 반환하며 쿠키가 없어도 성공한다.
- 갱신과 로그아웃은 같은 출처에서 `X-FoodLab-Auth: 1` 헤더와 함께 호출한다. 브라우저는 `food_refresh` 쿠키를 자동으로 보낸다. 인증 경로에는 액세스 토큰 헤더가 필요 없다.
- 리프레시 쿠키에는 `HttpOnly`, `Secure`, `SameSite=Strict` 및 `Path=/api/v1/auth`를 적용한다. 로컬 HTTP 개발 환경에서는 `FOOD_REFRESH_COOKIE_SECURE=false`로 설정할 수 있다.
- 중복 이메일은 `409`와 `DUPLICATE_EMAIL`을 반환한다. 로그인 정보나 리프레시 토큰이 유효하지 않으면 `401`과 `INVALID_CREDENTIALS`를 반환한다.
- `GET /members/me`와 `PATCH /members/me`는 Bearer JWT의 회원 ID를 사용한다. 수정 요청은 `{ "name": "새 이름" }`이며, 조회와 수정 모두 `200`과 `id`, `email`, `name`을 반환한다. 표시 이름은 공백만으로 구성할 수 없으며 최대 30자다.

## 요리

| 메서드 | 경로 | 접근 | 설명 |
| --- | --- | --- | --- |
| GET | `/dishes` | 공개 | 이름 검색, 정렬, 페이지네이션 |
| GET | `/dishes/{dishId}` | 공개 | 작성자, 요리 기본 정보, 평가 집계 및 재료 조회 |
| POST | `/dishes` | 회원 | 요리 기본 정보와 재료 등록 |
| PUT / DELETE | `/dishes/{dishId}` | 작성자 | 요리 기본 정보·재료 수정 / 요리 삭제 |

- 등록·수정 요청은 `name`, `description`, 문자열 `imageId`가 모두 필수다. `imageId`는 요리의 대표 이미지 키로 저장한다. 소개는 UTF-8 기준 최대 65,535바이트다.
- 등록은 `201`과 `{ "dishId": 1 }` 및 상세 경로의 `Location` 헤더를 반환한다. 수정·삭제는 `204`를 반환한다.
- 상세 응답에는 목록 항목과 같은 형태의 `summary`, `description`, `authorId`, `authorName`이 들어간다. 목록은 기본 최신순, 페이지 크기 기본 20건, 최대 100건이다.
- 상세 응답의 `materials`에는 재료별 `materialId`, `name`, `quantity`, `unit`이 들어간다. `materialId`는 공통 재료의 ID다. 수량이 없는 재료는 `quantity: null`로 반환하고, 연결된 재료가 없으면 `materials: []`를 반환한다.
- 등록·수정의 `materials` 항목에는 기존 `materialId` 또는 재료 `name` 중 하나와 `unit`, 선택적인 `quantity`를 전달한다. 이름은 공백과 대소문자를 정규화해 기존 재료를 재사용한다. 수량은 양수이며 소수점 이하 최대 3자리다. 같은 재료가 한 요청에 두 번 등장하면 `400`을 반환한다.
- 수정 시 `materials` 배열을 보내면 재료 목록 전체를 교체한다. 빈 배열은 연결을 모두 제거하고, 필드를 생략하거나 `null`을 보내면 기존 목록을 유지한다.
- 요리 목록은 `q`(요리명), `sort`(`latest`, `taste`, `effort`, `value`, `efficiency`), `page`, `size`를 받는다.

## 동료 검증

| 메서드 | 경로 | 접근 | 설명 |
| --- | --- | --- | --- |
| GET | `/dishes/{dishId}/reviews` | 공개 | 요리별 평가 목록 |
| POST | `/dishes/{dishId}/reviews` | 회원 | 다른 회원의 요리에 평가 작성 |
| PATCH / DELETE | `/dishes/{dishId}/reviews/{reviewId}` | 평가 작성자 | 내 평가 수정 / 삭제 |

- 평가 등록에는 `effort`(조리 편의성), `taste`(맛), `value`(경제성) 세 점수가 모두 필요하며 각 값은 1~5 정수다. `effort`는 5점이 가장 쉽고, 모든 항목은 점수가 높을수록 좋다. 회원당 요리별 평가 1건을 허용하며 자기 요리는 평가할 수 없다.
- API는 숫자 점수를 전달한다. 화면은 기획서의 평가 문구를 항목과 점수에 맞춰 표시한다.
- 평가 목록은 최신 등록순이며 `page`와 `size`를 받는다. 기본값은 0과 20, 최대 페이지 크기는 100이다. 목록 항목에는 `id`, `foodId`, `authorId`, 세 점수, `createdAt`, `updatedAt`이 들어간다.
- 등록은 `201`과 `{ "reviewId": 1 }`을 반환한다. 수정은 점수를 하나 이상 받아 전달된 항목만 변경한다. 수정·삭제는 `204`, 중복 평가는 `409`와 `DUPLICATE_REVIEW`를 반환한다.
- 요리 응답에 항목별 평균, 세 평균의 산술평균인 효율 지수, 평가 인원수를 포함한다. 평가가 없으면 평균과 효율 지수는 `null`, 인원수는 `0`으로 반환한다.

## 이후 구현 · 식재료, 조리 단계, 이미지 및 물자 조달

| 메서드 | 경로 | 접근 | 설명 |
| --- | --- | --- | --- |
| GET | `/ingredients` | 공개 | `q`로 기존 식재료 자동완성 검색 |
| POST | `/images` | 회원 | 이미지 파일 한 장 업로드 후 `imageId` 반환 |
| GET | `/ingredients/{ingredientId}/products` | 공개 | 식재료별 상품을 판매가 오름차순으로 조회 |

상품명, 판매가, 판매처, 이미지, 구매 링크, 가격 조회 시각을 제공한다. 최저가는 조회 결과 기준이다. 외부 API 장애는 상품 조회 요청에서 처리하며 요리 조회는 독립적으로 동작한다.

- 요리 등록·수정에 조리 단계 `steps`를 추가한다.
- 각 조리 단계는 `imageId`와 `instruction`으로 구성하고 배열 순서를 조리 순서로 사용한다. 카드 사진은 화면에서 1:1 비율로 표시한다.
- 요리 검색에 보유 식재료의 `ingredientIds`를 추가하고 결과에 부족한 식재료를 표시한다. 조합 검색의 결과 포함 기준은 별도 검토한다.

## 공통 응답

- 목록은 `items`, `page`, `size`, `totalElements`를 반환한다. 페이지 번호는 0부터 시작한다.
- 생성 성공은 `201`, 삭제 성공은 `204`를 반환한다. 오류 응답에는 `code`와 `message`를 담는다.
- 잘못된 요청은 `400`, 인증 필요는 `401`, 권한 없음은 `403`, 리소스 없음은 `404`, 중복 평가는 `409`를 반환한다.
- Bearer 토큰이 없거나 유효하지 않으면 `401`과 `UNAUTHORIZED`를, 지원하지 않는 요청 형식은 `415`와 `UNSUPPORTED_MEDIA_TYPE`을 반환한다.
